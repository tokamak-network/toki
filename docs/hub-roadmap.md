# Toki 허브 & 생태계 로드맵

> **작성:** 2026-06-09 · **상태:** A 착수, B 대기
> **한 줄:** Toki를 "스테이킹 전용 앱" → **임베디드 계정 기반 미니 월렛 + 생태계 앱 런처(게이트웨이)** 로 진화.

## 0. 포지셔닝 (왜)

- **타깃:** 거래소에 TON을 사두고 그냥 보유만 하는, 온체인 무경험·블록체인 무지식 유저.
- **목표:** 잠든 TON을 **스테이킹**으로 옮겨 첫 온체인 경험 → **토키가 게이트웨이**가 되어 Tokamak 생태계(프라이빗 송금·게임 등)로 유입.
- **자산:** 이미 Privy 임베디드 지갑 + EIP-7702 스마트계정 + 세션키 + TON 페이마스터(가스리스) 보유 → "지갑"의 어려운 부분은 풀려 있음. 남은 건 **허브 UI + 생태계 연결**.
- 관련 메모리: 게이트웨이 전략 / 온보딩 익스텐션.

## 1. 개발 순서

| 트랙 | 내용 | 상태 | 비고 |
|---|---|---|---|
| **A. 허브 셸** | 로그인 후 홈 = 미니 지갑 + 앱 런처 | **착수** | 프론트 only, 완성 가능 단위 |
| **B. 프라이빗 송금** | zkEVM Private App Channels 위 송금/인출 | 대기 | `docs/private-transfer-integration-plan.md` (M0~M4, 프루버 워커 인프라 필요) |
| **C. 게임 등** | 세션키·페이마스터로 무서명/무가스 온체인 게임 | 후순위 | Toki는 계정/지갑 rails 제공 |

> **A → B → C.** B/C는 모두 A(허브)의 런처 카드를 진입점으로 삼는다. 그래서 A를 먼저 깐다.

## 2. 트랙 A — 허브 셸 (UI/UX)

### 정체
`/dashboard`를 **대체**하는 로그인 후 홈. "내 TON이 여기 있고, 뭘 할 수 있는지"를 한 화면에.

### 정보구조
```
로그인 → /dashboard (허브)
  ├─ 인사 (토키 마스코트, 비차단 1줄)
  ├─ 지갑: 잔액(TON 중심) + 받기(QR/주소) [보내기는 = 프라이빗 송금 앱, 트랙 B]
  ├─ 앱 런처
  │    ├─ 스테이킹 [LIVE] → /staking
  │    ├─ 프라이빗 송금 [곧 출시] → /private-transfer (트랙 B 자리표시)
  │    ├─ 게임 [곧 출시]
  │    └─ 둘러보기 → /explore (생태계 36서비스)
  └─ 상태: 스테이킹 중 / 세뇨리지 / 넛지
```

### 레이아웃 (모바일 우선, 데스크탑 = 모바일 확장)
```
(토키 미니) 안녕 ○○!  ← 비차단 인사
─────────────────────
내 지갑   1,250 TON  ≈₩…
[받기 ▣QR]            ← 보내기 버튼 없음(송금=프라이빗 송금 앱)
· 스테이킹 중 800 TON +APR
─────────────────────
무엇을 해볼까?
[💠 스테이킹 LIVE→][🕶 프라이빗송금 곧]
[🎮 게임 곧       ][🧭 둘러보기 →]
```

### 컴포넌트 — 재사용 vs 신규
- **재사용:** `DashboardContent`의 잔액/주소/복사 로직, `explore`의 서비스카드 패턴, `StakingSummaryCard`, 마스코트 무드 스프라이트, 디자인 토큰(`accent-cyan #22d3ee` 등), `.card`.
- **신규:** `WalletMiniCard`(잔액+받기 QR), 앱 런처 카드(LIVE/곧 배지 + 내부 라우팅), 비차단 인사, `/private-transfer` 자리표시 페이지.

### 데이터 (`public/data/services.json` 확장)
1st-party 앱과 외부 생태계를 구분:
```jsonc
{ "id":"staking", "kind":"app", "route":"/staking", "status":"live", ... }
{ "id":"private-transfer", "kind":"app", "route":"/private-transfer", "status":"soon", ... }
```
허브 런처 = `kind:"app"`, explore = 전체.

### 상태 분기
- 잔액 0 → "거래소에서 TON 받아오자"(온보딩/익스텐션 유도)
- TON 있음·스테이킹 0 → "놀리지 말고 스테이킹!" 강조
- 스테이킹 중 → 세뇨리지·APR 인라인
- 곧 출시 앱 → 비활성 카드 + "출시 알림"

### A의 단계
- **2a (현재 ralph 범위):** 허브 셸 = 인사 + 지갑(잔액+받기) + 런처 그리드 + `/private-transfer` 자리표시 + i18n. **일반 보내기 없음.** 검증: `npx tsc --noEmit` + `next lint`(시각 확인은 사용자 dev 서버).
- **2b (후속):** 받기 고도화, 활동 내역. (※ 일반 송금은 만들지 않음 — 송금 = 트랙 B)

## 3. 트랙 B — 프라이빗 송금 (요약, 상세는 별도 문서)

- **상세:** `docs/private-transfer-integration-plan.md` (Plan A 확정, M0~M4).
- **요지:** Tokamak Private App Channels(zk note pool, 같은 TON·같은 L1) 위. 무거운 prover/제출은 **toki 서버 워커**(Docker+Rust+CRS), 유저는 브라우저 서명만, 메인 자금 L1 tx는 클라 서명. Sepolia 파일럿 → 메인넷 게이트.
- **허브 연결:** 허브 런처의 "프라이빗 송금" 카드 → `/private-transfer`. A의 자리표시 페이지를 B에서 실제 패널로 교체.
- **인프라 게이트(ralph 범위 밖):** Sepolia 자체배포, 프루버 워커 호스팅, 증명비용 측정, `ChannelManager.msg.sender` 확인 → M0 스파이크부터.

## 4. 횡단 원칙

- 공유 **임베디드 스마트계정** 하나로 모든 트랙. 키 관리 자체구현 금지(Privy/표준).
